# 0001 — Rust for the core

**Status:** Accepted. Pre-decided in the project brief; recorded here with the reasoning.

## Context

The core owns buffers, extmarks, layout state and the agent loop, and is mutated from a terminal
input thread, a JavaScript runtime thread, and one task per in-flight provider stream.

## Decision

Rust.

## Why

The load-bearing property is not speed, it is that **the aliasing rules make the single-writer
design checkable**. `Editor` is mutated from exactly one task; the borrow checker enforces that
rather than a comment asking people to be careful. A buffer being spliced while a renderer walks it
is a class of bug that cannot be written here.

Two secondary reasons: the ecosystem for the specific things this project needs (ratatui,
deno_core, a competent SSE stack) is strong, and shipping a terminal tool as a single static binary
with no runtime dependency is worth a lot for adoption.

## Costs

Compile times are the real price — the dependency tree is 522 crates and a clean build of the v8
bindings takes minutes. Mitigated by keeping `neosh-script` (the only crate that pulls v8) at the
edge of the graph, so day-to-day work on the core rebuilds in seconds.
