# v0.4.7 — the swarm reads as local

Work on another computer was drawn as a different *kind* of thing. It is not: it is the same work in a different place, and this release is the panel finally saying so.

## One row per repository, wherever its checkouts are

A repository you have on two machines was two rows. The panel matched them on a project key the local side never had — it inferred one from the remote agent's working directory, so the two only met when both machines happened to have the repository at the same absolute path. They never do. So the repository you were sitting in appeared once as yours, and once again below as a project you had apparently never heard of, named after whichever remote conversation happened to sort first — which for a worktree is `neosh · fix/thing`, a display string being used as an identity.

Now a project is its git identity and a checkout is a machine and a path:

```
 PROJECTS
──────────────────────────────────
 ▾ neosh                         6
   ▸ Chasing the flake         12m
   · Rework the tab bar        @
   ▾ ⎇ fix/composer-paste        2
     · Try the grapheme path
   ▾ ⎇ fix/tab-strip @           1
     · Nearly there            @
 ▾ api @                         3
   · Rate limiting             @
```

One row for the repository. Its conversations here and its conversations over there in the same list under it. Every other checkout — a worktree here, a worktree there, the main one there — a row one level down, named by its branch. `api` is a repository this machine has no clone of at all, which is still somewhere you can see and start work.

Two checkouts of one branch on two machines stay two rows. Same name, different disks, different uncommitted work; merging them would be a claim that is false.

## `@`, and only where it is news

A cloud is the world's mark for "not on this machine" everywhere except a terminal, where it reads as a cloud *service* — the wrong idea about a laptop on the same desk. Anyone who has typed `ssh you@box` already knows what `@` means. Green when the link is up, pulsing amber while it is being dialled or waiting for somebody to allow this computer over there, dim when nothing is dialling it.

A repository row wears one only when the repository is **not** here as well: on a swarm of two machines nearly every row is partly elsewhere, and a column spent on something true of everything says nothing. Where it is news is a repository you have no clone of — the row you would otherwise press `↵` on expecting your own files.

A project a peer has with nothing open in it now appears at all, which it never did.

## A shell over there

`t` on any row opens a terminal in that project, on whichever machine the project is on. What a terminal is *for* is running something beside an agent that has just finished, and where that agent is running is where the terminal has to be.

The shell runs there and the terminal emulator runs here — how ssh is arranged, and for its reasons: full-screen programs work, and the side doing the drawing is the side that knows how wide it is. Every key goes to the child, `^C` interrupts *it*, and `<C-w>` is the way out.

It is **off by default** and asked for separately from steering:

```toml
[swarm]
accepts_commands = true    # peers may steer agents here
accepts_shells   = true    # peers may open a shell here
```

Starting an agent over there is a thing with a permission layer over it, a transcript, and somebody who can read afterwards what it did. A pty is a prompt — your shell, your environment, your credentials, and nothing above it to say no. The machine it runs on says so on screen each time one is opened, and closes every one of them when the link that asked for it goes away.

Nothing on the wire breaks: a v0.4.6 machine and a v0.4.7 machine still talk, and simply do not offer each other shells.

## Smaller things

- `c` and `C` connect to and disconnect from the machine a row is about. A project greyed with a dim `@` is the moment you want to reconnect, and going to `^J` to do it means first knowing `^J` exists.
- **The pull spinner keeps spinning when you look at it.** The cursor was drawn as a highlight across the whole row, which won every character it covered — and a run animates because its winning highlight says so. It is a band now, under the row's own marks rather than over them, so the git badge and the favourite's star keep their colours under the cursor too.
- `^N` stops asking which computer when none of the connected ones has the repository you are in. One possible answer is not a decision.
- A machine that has not allowed this one yet no longer contributes rows to your panel.
- `J`/`K` on a worktree move it again.

## Keys

| Key | Does |
| --- | --- |
| `t` | A terminal in this project — here, or on the machine the row is on |
| `c` `C` | Connect to that computer, or disconnect from it |

`^J` is still where a machine is added, renamed or removed.
