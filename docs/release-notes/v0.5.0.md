# v0.5.0 — another computer's conversation works like one of yours

Opening a conversation that lives on another paired computer now opens it as a conversation: the full transcript with its tool cards, live turns, and a composer that sends to that machine. `↵` on its row puts the keyboard in it, just as it does for one of yours. Before this release, you got a read-only window with a one-line prompt.

Every key does to it what it does to a local one, carried out on that machine. `^P` and `^E` list **that machine's** providers, models and settings, and the footer shows its model, mode and context meter. `^N` starts a new conversation beside it over there. `<C-w>T` opens a shell on that machine in the conversation's directory (it needs `accepts_shells` there). Renaming and archiving work too; deleting is refused, because only that machine can do it. When its agent asks a question, the question appears here and on the other machine at the same time, and whichever is answered first wins. Permission prompts come across the same way when that machine sets `accepts_approvals`.

The project panel now has one section per computer. Each machine gets a short code (`@lb`) and a colour of its own, a checkout on another version shows as a block of its own, and the rail down the side is gone. Folding a remote row no longer turns it into a project of yours.

Also new: a settings panel (`,` in the project panel, or `/settings`) that saves into `config.toml` without disturbing your comments; `agent.append_prompt`, standing instructions sent with every message; `git.pull.auto`, which keeps main checkouts fast-forwarded; and pasting into a panel that has the keyboard now goes to that panel.

Both computers need 0.5.0 for all of this. An older one on the other end still streams its conversations, but `^P` there lists this machine's models and questions are not relayed. After upgrading, run `neosh stop` and start `neosh` again on each machine: a running workspace keeps executing the old binary.
