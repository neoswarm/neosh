# v0.4.8 — reliable Codex turns and visible speed controls

Codex conversations now stay running until their own turn finishes, and supported models expose Standard/Fast speed controls beside their reasoning options.

## Conversation lifecycle fixes

- A sub-agent finishing no longer marks the main conversation done, resets its streamed answer, or overwrites its token usage. Notifications are matched to the conversation's thread and turn, including notifications arriving before the turn-start acknowledgement.
- An abandoned response is interrupted and drained before the connection accepts the next message, keeping leftover output out of the next answer.
- Cancelling before the turn ID arrives now sends the interrupt as soon as the acknowledgement identifies it.
- Rejected turn-start requests report their error and preserve the existing thread, so correcting a model or option does not discard the agent's conversation history.

These fixes address conversations that appeared done while the main agent was still working, then suddenly showed old activity under a new message.

## Standard or Fast, visible and changeable

Open **Ctrl+E**, move to **Speed** with **j/k**, and choose with **h/l** or the arrow keys. Models advertising Fast offer it alongside Standard; additional tiers retain the names and descriptions supplied by Codex.

The footer shows the selected speed, including the default for conversations with no saved speed option. Changes apply to the next turn. Choosing Standard explicitly clears a previous Fast setting. Older Codex versions' speed-tier metadata is supported too.

Speed controls use the existing public model-options API, so themes, keybindings and replacement model panels continue to work through the same plugin surface.

## Verification

The changes passed 242 provider unit tests, 9 app-server integration tests, the real-binary Standard → Fast → Standard UI test, and TypeScript checks. The four lifecycle regressions were also verified to fail against the original driver. Full repository CI passed before merging PR #114.

After upgrading, restart the workspace once active turns have finished so the running daemon loads the new version.
